How EF Core Works (and What Costs Time)

You can't optimize what you don't understand. This lesson walks through what EF Core does between your LINQ query and the database, and shows where the time goes.

⏱ 20 min

By the end of this lesson you will be able to

  • Explain the roles of DbContext, DbSet<T>, the model and the change tracker.
  • Describe the query pipeline: LINQ → expression tree → SQL → materialization.
  • Name the five main cost centres of EF Core performance.
  • Set up the sample ShopContext used throughout this course.

What EF Core is

Entity Framework Core (EF Core) is Microsoft's open-source object-relational mapper (ORM) for .NET. You work with ordinary C# classes (entities), and EF Core translates your LINQ queries into SQL. It also tracks changes to your objects and writes them back to the database. It supports SQL Server, PostgreSQL (Npgsql), SQLite, MySQL, Oracle, Azure Cosmos DB and more through database providers.

This course targets EF Core 10, the Long-Term Support release that shipped with .NET 10 in November 2025. Nearly everything also applies to EF Core 8 and 9. Where a feature is version-specific, the lesson says so.

public class ShopContext : DbContext
{
    public ShopContext(DbContextOptions<ShopContext> options) : base(options) { }

    public DbSet<Customer> Customers => Set<Customer>();
    public DbSet<Order> Orders => Set<Order>();

        modelBuilder.ApplyConfigurationsFromAssembly(typeof(ShopContext).Assembly);
    }

The life of a query

When you write:

var orders = await db.Orders
    .Where(o => o.CustomerId == customerId && o.Status == OrderStatus.Paid)
    .OrderByDescending(o => o.PlacedUtc)
    .ToListAsync();

EF Core runs these steps:

  1. Expression tree. The C# compiler turns your lambdas into an expression tree: data that describes the code rather than compiled IL.
  2. Cache lookup. EF checks its query cache for a query with the same shape. Captured variables such as customerId become parameters, so the same query with a different id is a cache hit.
  3. Compilation (on a miss). EF translates the tree into SQL plus a shaper, the code that turns rows into objects. This is the most expensive in-process step.
  4. Execution. EF opens a connection (from ADO.NET's connection pool), sends the SQL with parameters and waits for the database. This network round trip plus the database's own work usually dominates total time.
  5. Materialization. EF reads each row and creates entity instances.
  6. Tracking. For tracking queries, EF registers each entity in the change tracker, applies identity resolution and fixes up navigation properties.
SELECT [o].[Id], [o].[CustomerId], [o].[PlacedUtc], [o].[Status], [o].[Total]
FROM [Orders] AS [o]
WHERE [o].[CustomerId] = @__customerId_0 AND [o].[Status] = 1
ORDER BY [o].[PlacedUtc] DESC
Rule of thumb In most applications the database dominates: round trips, rows scanned, rows transferred. Fix data access patterns first (what you fetch and how many queries you send). Micro-optimize EF itself last.

The unit-of-work pattern

A DbContext is a unit of work. You load some entities, change them in memory, then call SaveChanges(). EF compares current values with the snapshot it took when loading, then emits the minimum INSERT, UPDATE and DELETE statements, batched together and wrapped in a transaction.

await using var db = new ShopContext(options);

var product = await db.Products.SingleAsync(p => p.Sku == "BOOK-42");
product.Price = 19.99m;                 // only changes memory

await db.SaveChangesAsync();            // UPDATE [Products] SET [Price] = @p0 WHERE [Id] = @p1
A DbContext is not thread-safe Never share one context across threads or run two operations on it in parallel (for example, Task.WhenAll over two queries on the same context). EF throws InvalidOperationException: A second operation was started on this context instance…. Use one context per unit of work, which in ASP.NET Core means one per request.

Exercise

🛠 Build the playground

  1. Create a console app: dotnet new console -n EfPlayground.
  2. Add packages: dotnet add package Microsoft.EntityFrameworkCore.SqlServer (or .Sqlite) and dotnet add package Microsoft.EntityFrameworkCore.Design.
  3. Paste the model and ShopContext above.
  4. Install the CLI tool: dotnet tool install --global dotnet-ef.
  5. Create the database: dotnet ef migrations add Initial, then dotnet ef database update.
  6. Write a seeding loop that inserts 1,000 customers with 10 orders each. You'll reuse this data in later lessons.
Show a seeding snippet 
var rnd = new Random(42);
var category = new Category { Name = "Books" };
var products = Enumerable.Range(1, 200).Select(i => new Product
{
    Sku = $"SKU-{i:D5}", Name = $"Product {i}", Description = new string('x', 2000),
    Price = rnd.Next(5, 200), Category = category
}).ToList();
db.Products.AddRange(products);

for (int c = 0; c < 1000; c++)
{
    var customer = new Customer { Name = $"Customer {c}", Email = $"c{c}@shop.test", CreatedUtc = DateTime.UtcNow };
    for (int o = 0; o < 10; o++)
    {
        var order = new Order { PlacedUtc = DateTime.UtcNow.AddDays(-rnd.Next(365)), Status = (OrderStatus)rnd.Next(4) };
        for (int l = 0; l < 3; l++)
        {
            var p = products[rnd.Next(products.Count)];
            order.Lines.Add(new OrderLine { Product = p, Quantity = rnd.Next(1, 5), UnitPrice = p.Price });
        }
        order.Total = order.Lines.Sum(x => x.Quantity * x.UnitPrice);
        customer.Orders.Add(order);
    }
    db.Customers.Add(customer);
}
await db.SaveChangesAsync();   // EF batches these inserts. Lesson 11 explains how.

Quiz

When does EF Core send SQL to the database for db.Orders.Where(o => o.Total > 100)?

LINQ queries against a DbSet are deferred. They only build an expression tree until you enumerate them.

Which of these is usually the largest cost in a slow EF Core endpoint?

Network latency and database work usually dwarf in-process overhead. Fix query count and data volume first.

Why is changing customerId between calls still a query-cache hit?

Closure variables become parameters (@__customerId_0). Lesson 16 shows how constants can break this.
